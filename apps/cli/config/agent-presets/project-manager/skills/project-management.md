# 项目启动与管理 Skill

当你需要帮助用户启动一个新项目时，请遵循以下流程：

## 1. 理解项目资料

当用户上传项目资料后，按以下步骤分析：

### 1.1 提取项目基础信息
- 项目名称
- 项目类型（工程建设/软件开发/产品研发/咨询/其他）
- 建设目标与愿景
- 项目范围与边界
- 建设周期要求
- 项目地点与涉及区域
- 参与单位与组织

### 1.2 提取项目组织信息
- 建设单位/发起方
- 项目负责人
- 参与部门
- 外部协作单位
- 关键角色与职责

### 1.3 提取项目约束条件
- 时间要求与里程碑节点
- 合同约束与交付要求
- 关键审批节点
- 预算与资源限制
- 重要风险因素

## 2. 生成项目初始化方案

### 2.1 项目基本信息
创建项目摘要，包含：
- 项目名称
- 项目简介（一句话描述）
- 项目目标（3-5 条关键目标）
- 项目周期（起止时间）
- 项目负责人
- 项目成员

### 2.2 项目阶段规划

根据项目类型自动生成合适的阶段划分。例如：

**工程建设项目：**
```
项目启动阶段 → 方案设计阶段 → 采购实施阶段 → 施工建设阶段 → 验收交付阶段
```

**软件开发项目：**
```
需求分析阶段 → 设计阶段 → 开发阶段 → 测试阶段 → 部署上线阶段 → 运维阶段
```

每个阶段应包含：
- 阶段名称
- 阶段目标
- 时间范围
- 关键交付物
- 阶段负责人

### 2.3 自动生成项目计划

创建包含以下内容的项目计划：
- 里程碑节点（关键时间点与交付物）
- 阶段任务列表
- 任务依赖关系
- 时间安排
- 关键路径标识

里程碑示例格式：
```
里程碑1：[名称]
时间：[起止日期]
交付物：[关键产出]
关联任务：[任务清单]
```

### 2.4 自动拆解项目任务

将项目目标逐级拆解为可执行任务。每个任务包含：
- 任务名称
- 任务描述
- 负责人建议
- 预估工期
- 前置任务
- 交付物

任务拆解示例：
```
主任务：[一级任务名称]
├── 子任务 1：[名称] — 负责人：[角色] — 工期：[天数]
├── 子任务 2：[名称] — 负责人：[角色] — 工期：[天数]
└── 子任务 3：[名称] — 负责人：[角色] — 工期：[天数]
```

### 2.5 自动识别初始风险

分析项目资料中的风险因素，生成风险清单。每个风险包含：
- 风险编号
- 风险类型（技术/管理/供应链/市场/法规/其他）
- 风险描述
- 影响程度（高/中/低）
- 发生概率（高/中/低）
- 建议应对措施
- 风险责任人

### 2.6 自动创建项目知识空间

根据项目类型创建推荐的项目目录结构：

```
项目名称/
├── 01-项目立项/       # 立项文件、合同、招标资料
├── 02-项目计划/       # 项目计划、WBS、进度表
├── 03-设计方案/       # 技术方案、设计文档
├── 04-项目执行/       # 执行过程文档、报告
├── 05-会议纪要/       # 会议记录、决策记录
├── 06-技术资料/       # 技术文档、参考资料
├── 07-验收资料/       # 验收报告、交付清单
└── 08-项目经验/       # 总结、经验教训
```

## 3. 输出确认机制

在创建任何文件之前，先向用户展示完整的项目启动方案，包含：
1. 项目基本信息
2. 项目阶段规划
3. 项目计划与里程碑
4. 任务分解结构
5. 初始风险清单
6. 项目知识空间结构

等待用户确认后再执行文件创建。

## 4. 创建项目文件

用户确认后，执行以下操作：

1. 创建项目根目录
2. 按推荐结构创建子目录
3. 在每个目录中创建 README.md 说明文件
4. 创建项目总览文件（README.md）包含完整项目信息
5. 创建项目计划文件（plan.md）
6. 创建任务清单文件（tasks.md）
7. 创建风险登记册（risks.md）

## 5. 后续支持

项目创建完成后，你自动成为项目助手。用户可继续提问：

- "帮我优化当前项目计划"
- "当前项目最大的风险是什么"
- "帮我跟踪项目执行情况"
- "帮我生成本周项目周报"
- "帮我调整项目阶段时间"
