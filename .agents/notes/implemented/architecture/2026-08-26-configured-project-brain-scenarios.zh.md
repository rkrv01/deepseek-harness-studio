# Agent Note: 配置驱动的项目智脑场景与命名对话界面

Status: implemented

[English](2026-08-26-configured-project-brain-scenarios.md) | 中文

## Problem

项目智脑预设最初包含两个脚本化演示，其触发路由、生命周期名称、编辑器状态、流式节奏、消息标记和结果卡片在浏览器插件与确定性模型适配器中重复实现。浏览器还为所有会话共用一个可变状态仓库。因此，增加场景需要协调修改 TypeScript 和 TSX，切换会话还可能清除控件或将其归属到错误消息。这使剩余演示的交付变慢，也容易让交互式“今日工作”界面变成又一组场景专用分支。

## Decision

项目智脑场景集中登记在 `packages/client/ui-project-brain/src/scenarios.json`。每个条目拥有触发语句、思考文案、展示模式与命名模板、流式节奏、审核文案和执行步骤。`scenario-registry.ts` 是唯一匹配器，并定义一种用于修订和确认的版本化私有信封。浏览器和确定性适配器共同消费该注册表，不再维护两棵独立的触发树。

浏览器为每个会话保留一个场景状态仓库。状态仓库使用共享生命周期阶段（`analyzing`、`review-ready`、`revising`、`executing`、`syncing`、`failed` 和 `completed`），并携带当前项目方案或会议行动项等场景数据。只有严格私有标记识别的助手消息下方才渲染对应控件。历史消息通过同一标记恢复审核数据，用户消息投影会在渲染与复制时移除私有信封。

展示有两种模式。`document` 使用原生 Markdown 和图表渲染器。`surface` 指定允许列表中的 React 模板，并通过版本化标记传入 JSON 数据，不执行场景数据中的任意 HTML。`my-day-workbench` 和 `project-copilot-dashboard` 证明场景可以在对话中呈现具体的交互式工作界面，同时保持文案和数据由配置或固定数据所有。`executive-briefing` 场景保持文档优先，通过私有确认标记和紧凑回执卡片完成闭环，因为它的价值在于生成汇报材料，而不是提供可编辑控制面板。

## Alternatives considered

**继续为每个场景添加一个组件和一条路由分支。** 这能保留最大的局部自由度，但会重复生命周期和协议行为，也会让每个仅内容不同的演示都需要同时修改客户端和适配器代码。

**在场景 JSON 中存储任意 HTML。** 这能快速粘贴原型，但会放弃组件一致性、可访问性、响应式行为、类型检查和安全的渲染策略。命名 React 模板在保留这些性质的同时，仍使场景选择和数据保持声明式。

**使用一个全局浏览器状态仓库，并在会话变更时重置。** 这表面上更简单，却会让历史控件依赖最近选中的会话。按会话分配的状态仓库使场景状态与渲染它的会话作用域插槽保持一致。

## Consequences

项目启动和会议执行演示共享路由、阶段、私有协议和会话归属。会议修订现在会进入审核卡片、确认载荷、执行统计和项目快照，不再只修改 Markdown。首批五个演示快捷入口使用注册表中的建议语句并通过原生输入框提交，因此场景入口保持可见，但不会绑定到固定结果区域。未来的文档式场景通常只需新增注册条目、数据和回复模板；未来的交互式场景另外增加一个命名界面组件。真正新的交互模式仍可能需要 TypeScript，但不需要另外实现提交路由器或场景生命周期。

场景注册表和界面信封是版本为 `1` 的内部演示格式，不支持的版本会被拒绝。内存中的会话状态映射在浏览器插件生命期内持续存在，不是持久化的项目数据。聚焦组件和适配器测试固定了触发优先级、私有消息投影、修订连续性、动态会议统计和命名的今日工作界面。
