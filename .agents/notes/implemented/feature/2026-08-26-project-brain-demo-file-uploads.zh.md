# Agent Note: Project Brain demo file uploads

Status: implemented

[English](2026-08-26-project-brain-demo-file-uploads.md) | 中文

## 问题

项目智脑场景需要在领导汇报演示中呈现可见的文件上下文，并提供可下载的汇报材料，但输入框此前刻意没有文件选择器和上传协议。真实的存储、解析和持久化路径会超出演示范围，并造成模拟场景引擎无法兑现的产品承诺。

## 决策

项目智脑会话将粘贴和整页拖放路由到混合入口，并在命令启动器旁显示显式回形针控件。隐藏的多选文件选择器接受图片以及 `.txt`、`.md`、`.markdown`、`.doc`、`.docx`、`.xls`、`.xlsx` 和 `.pdf`。遇到不支持的文档时，会在注册前整批拒绝；受支持的图片继续沿用既有图片限制和预览。

文档保持为仅存在于运行时的输入框芯片。注册成功后，有序草稿 id 进入输入状态；提交请求携带 `documentIds` 和 `{ name, type, size }` 形式的 `documentMetas`。只有项目智脑项目方案处理器消费这些元数据，并把它们写入确定性方案快照。文档字节留在浏览器内：解析器不读取，提供方请求不包含，传输载荷和持久历史也不保存。普通发送成功后释放这些注册；普通会话继续使用纯图片入口。

集团领导汇报回执把四个配置文件渲染为无障碍列表，包括类型徽标、名称、展示大小和下载操作。点击下载会创建本地 Blob：Markdown 使用 UTF-8 文本，Word、PowerPoint 和 Excel 使用 `fflate` 的 store-mode ZIP 打包最小 OOXML 组成部分。合成点击后立即撤销对象 URL，结果卡明确标注内容仅为界面演示数据。

## 验证

Conversation、Attachment 和 Project Brain 聚焦测试覆盖混合粘贴／拖放路由、不支持批次拒绝、文档芯片、提交请求 id 与元数据、处理器到方案的传递、材料 MIME 类型和 OOXML 内容、下载交互，以及普通会话未变化的纯图片路由。合并运行以 44 个文件和 559 个用例全部通过结束；TypeScript 编译另行检查。

## 曾考虑的替代方案

**手写 Office ZIP 编码器。** 拒绝，因为 `fflate` 是维护中的库，workspace JavaScript 已经可用，并且比第二个本地写入器更能处理 store-mode 打包细节。

**在服务端生成材料。** 拒绝，因为需求是前端演示；服务端生成会暗示持久产物、授权、生命周期所有权和清理责任，而本演示刻意不提供这些能力。

**像生产附件一样上传并解析文档。** 拒绝，因为演示只需要可见上下文。解析任意 Word、Excel 和 PDF 字节会增加安全与兼容义务，却不能改进脚本化场景。

## 后果

演示无需后端工作即可附加代表性文档，并向领导提供四个可下载产物。代价是文档只影响确定性场景快照，重新加载后消失，无法从历史重新打开，也不能被表述为真实上传或权威报告文件。
