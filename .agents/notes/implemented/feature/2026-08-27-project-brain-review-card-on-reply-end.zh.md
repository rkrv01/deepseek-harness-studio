# Agent Note: 项目智脑确认卡在回复结束时出现

状态：已实现

[English](2026-08-27-project-brain-review-card-on-reply-end.md) | 中文

## 问题

项目启动与会议场景的确认卡此前依赖提交时刻起算的固定定时器（14 秒与 7 秒）才变为可见。定时器与确定性流式输出互相赛跑：只要文档播放时长超过定时器，确认卡就会在正文已经播完之后才出现——这正是演示调优想避免的等待；而且一旦进一步放慢流式，超长回复结束后没有任何机制翻转阶段，问题会更严重。

与此同时节奏参数存在两处互相矛盾的来源。场景注册表为每个文档声明了 `{128 字 / 300 ms}`，而演示适配器对会议分析实际使用另一套硬编码的 `{192 字 / 220 ms}`（约 870 字/秒），注册表中的会议配置是死配置，无法通过注册表调节。

## 决策

就绪改为事件驱动。分析回复把私有标记保存在步骤数据中，因此当归属助手消息回合结束、`ProjectBrainTurnTail` 挂载时，一个 effect 会针对 project-launch 与 meeting-actions 两个场景把 `analyzing`/`revising` 翻转为 `review-ready`；store 动作保留既有阶段守卫，同时也防止旧回合把已完成会话拖回早期状态。两个提交时刻常量、五处 `setTimeout` 调用点和工作台修订定时器全部删除。

流式节奏只有一个来源：`scenarios.json`。适配器把每种回复 kind 解析到所属场景定义（新增导出的纯函数 `replyStreamScenario`），并用同一个分片文本生成器按需以场景思考文案开头；执行回执与平台重试保持专属呈现不变。五个场景现在统一放慢到可读速度（约 320 字/秒，会议约 500），让长文档在领导演示时可以逐段看清。

## 验证

演示适配器与浏览器插件的聚焦 Vitest 用例覆盖 kind 到场景节奏的解析、放慢后的注册表数值，以及新的 TurnTail 用例：挂载分析回合即翻转阶段并渲染确认卡、全程无定时器参与。`ui-conversation`、`ui-project-brain` 与 `project-brain-demo` 的 TypeScript 构建联合通过。每次正式演示前，真实浏览器流程仍是观感节奏的最后检查点。

## 已考虑的替代方案

**重新校准固定定时器去贴近流式时长。** 否决：这会在每次内容或节奏修改后重新引入竞态——7 秒 / 14 秒数值当初就是这样漂移的。

**在回合数据里暴露流式完成信号。** 否决：turn tail 本身只在回合结束后存在，挂载时机已经是完成信号；新加标记只增加协议面，不改变任何可观察行为。

## 后果

确认卡现在随正文播完立即出现在其下方；历史恢复复用同一套基于标记的归属规则，继续有效；后续调整节奏只需改一行 `scenarios.json`。代价是运行时节奏完全取决于注册表数值，删除某个场景 id 时必须同步更新 kind 映射表。

## 同日后续：尾部载荷也在按可见节奏播放（2026-08-27）

事件驱动翻转上线后暴露出此前被旧数字掩盖的第二个延迟源：会议分析文档以约 10KB 的百分号编码 `project-brain:scenario` 载荷收尾，而 `streamScenarioText` 对整段文本统一分片——最后一个可见字符之后，适配器还在按可见演示速度爬行几千个不可见字符，数秒后回合才结束。端到端实测会议全流程约 28 秒，其中约 20 秒是静默尾巴。

现在 `streamScenarioText` 会剥出末尾连续的 `<!-- project-brain:* -->` 标记（新增 `splitTrailingPrivateMarkers`），用一个不带延时的增量立即附加：回合在最后一个可见字符后立刻完成，且全部增量拼接仍与原文逐字节一致。实测演示环境回复耗时从约 28 秒降至约 8 秒，确认卡随即挂载。第一版正则静默失效的原因是真实标记里关键字与编码载荷之间有一个空格（`scenario %7B...`），被取值字符集拒绝；新模式显式建模 `<关键字> [空格 载荷]` 结构，并用假时钟回归用例同时锁住增量保真和可见字符后的耗时预算。验证本次修复还有一个重启教训：端口占用型服务“重启”后必须核对监听进程 PID 的启动时间——shell 链条一旦短路，旧进程会带着过期代码继续服务且不留任何报错。

## 同日第二批：按场景需求文档的内容打磨

第二轮演示调优重塑了输入区与三个场景表面。快捷入口现在常驻输入框上方（仅按预设与空草稿守卫），一个场景演示完可直接衔接下一个；输入框占位与拖拽遮罩为项目智脑会话新增了图片与文档混合提示；文档芯片限宽 280px，长名省略。会议修订现在像项目方案修订一样发送可读摘要并携带 `revision-summary` 载荷，自动复用既有折叠明细投影。托管场景改为回答「现状怎么样」，以项目经理汇报形态呈现（托管状态条、带已执行动作的 AI 跟进清单、只含异常的今日发现、收敛后的待决策事项、低权重项目全貌）；今日工作台升级为跨项目编排面板（三个项目统一编号排序、可以暂时放一放、今天已处理、完成后自动重排提示）。汇报确认卡改为六项材料复选（默认四项），只生成所选材料；回执从持久化 confirm 载荷恢复所选清单。汇报场景注册表节奏放慢至约 230 字/秒。

## 同日第三批：汇报下载切换为真实演示文件

汇报下载由浏览器端伪造的最小 OOXML 占位改为三个固定演示文件（口头稿.md、风险与协调事项.xlsx、PPT提纲.pptx），以 base64 常量原样内嵌进 `src/briefing-assets.ts`（从演示目录生成）。`createBriefingMaterialBlob` 现在解码这些真实字节（正确 MIME 与原文件内容），不再本地构造 OOXML；选择卡默认全选这三项、只生成所选，回执新增所选清单的一键全部下载。重新生成说明写在生成文件头注释里。

## 同日第七批：地址分离、开发者配置门控与看板优先小结

- 业务地址（`platformBaseUrl`，链接渲染 `${base}/business-xmzn/#/...`）与 demo-status 接口地址（`demoApiBaseUrl`，端点 = `${base}/api/demo/config`）拆分为两个独立设置字段、各有默认值——业务地址可能走代理，本地调试不便。`PROJECT_BRAIN_DEMO_STATUS_PATH` 是唯一的端点后缀常量；`DemoStatusSynchronizer` 继续接收 base 并只拼接一次路径（早期草稿让 getter 返回完整端点导致拼接了两次）。
- 设置分区改为「开发者配置」且默认隐藏：`settings.section` 插槽由 effect 监听 `localStorage['starlight:dev-mode']` 动态注册；控制台命令 `window.toStarlightDev()` 写键并刷新，分区内的「关闭开发者模式」按钮移除该键，直到再次执行命令。静态注册会泄漏一个空的导航入口，因此改为条件注册。
- 托管看板移除「托管权限模式」切换器；AI 小结回到纯 surface 标记回复，由 surface 渲染「看板在前、对话式小结气泡（`.narrativeBubble`）在后」——用户要求视觉顺序为看板 → 对话。

## 同日第八批：看板内联前置 + 小结真实文本

托管小结重新成为真正的 assistant 消息，且顺序为看板优先：回复以 surface 标记开头，ui-conversation 新增可选 `assistantSurface` 服务（与 `chatFileMentions` 同构），`AssistantMarkdown` 在首个文本块以完整 `project-brain:surface` 标记开头时调用它——载荷渲染为消息顶部的内联看板，其后被剥离的正文以普通 markdown 流式呈现在看板下方。turnTail 对 copilot surface 回合返回 null 避免重复，其他 surface（my-day 尾部标记）仍走 turnTail。`streamScenarioText` 新增对称的前导标记规则：开头连续私有标记不分速，看板在首个可见字符之前挂载。看板容器由窄化出血类改为 `.surfaceInline`（占满消息宽、不出血）。同时移除上一版的气泡变体；`.copilotGrid` 的 padding 改为 `20px 0`（保留垂直方向）；项目全貌新增状态对比：方案包卡按状态加左侧色条、状态/风险数值按档位着色（完成/正常/低风险绿、临期/中风险橙、滞后/高风险红）。

## 同日第九批：框架收敛——入口隐藏、临时开发者模式、可选固定工作区

- 侧栏只保留「插件中心/插件发现」：Preset 广场与应用中心的侧栏入口及其主页面不再注册（它们本是 ui-plugin-center 里的无条件注册；client 插件拿不到 cordis patch 配置，故为源码级演示收敛而非配置开关）。轨迹对话 tab 同样不再注册（数据视图、压缩定义与会话日志投影保留——仅 UI tab 移除，ConversationSession 的 `tabs.length > 1` 规则随之隐藏整行 tab）。
- 开发者模式改为严格临时：`isProjectBrainDevMode()` 为会话内状态（模块布尔 + 事件），刷新必然关闭；「关闭开发者模式」按钮删除——没有可持久化的东西，也无法被留在开启状态。
- 固定工作区开关为 `project-brain` 设置字段（`fixedWorkspace`，默认 false），在开发者分区中展示。开启后 demo 插件创建 `~/starlight_xmzn` 及同名工作区记录，网关随即加锁：create 忽略请求路径、rename/delete 返回新增的 `workspace-readonly` 错误码、list 只回固定目录。`fixedWorkspaceControl` 以 cordis service 承载开关，使 tsdown demo 产物与源码运行的网关共享同一实例（模块状态会跨两个模块图分裂）；`IWorkspaces` 新增公开 `refresh()` 以便开关切换时浏览器重新拉取列表。
