# 场景1：一句话启动一个项目 — 演示脚本

## 操作步骤

### 1. 准备工作
- 选择预设：「项目智脑」
- 确保工作区在项目根目录

### 2. 向 AI 输入
```
根据这些材料，帮我把项目初始化出来。
```

### 3. AI 输出内容

AI 将依次展示以下内容。每一步需要人工确认。

#### 步骤 3.1 — 项目信息分析摘要

AI 从文档中提取关键信息，以表格形式展示。

#### 步骤 3.2 — 项目启动方案 + 交互确认卡片

AI **一次性输出完整方案**（含 Mermaid 图表），**同时渲染 visualize 交互确认卡片**，不弹文字确认。卡片即确认工具。

| 板块 | 展示形式 | 说明 |
|------|---------|------|
| 项目信息卡 | 表格 | 项目名称、类型、周期、预算、负责人 |
| 项目目标 | 列表 | 3-5 条关键目标 |
| 阶段规划 | Mermaid 流程图 + 表格 | 阶段名称、时间、目标、交付物 |
| 任务分解 | 分级列表 | 每项含负责人、工期、前置任务 |
| 风险识别 | 表格 | 风险类型、描述、影响、概率、应对措施 |
| 知识空间 | 树形目录 | 项目目录结构 |
| 确认卡片 | visualize 交互卡片 | 可编辑所有字段，新增/删除行，确认提交 |

**Demo 模式特点**：无工具调用过程展示，无 Think 推理，无多余文字确认。方案和卡片一次性呈现。

用户编辑卡片并提交后，粘贴数据回复，进入步骤 3.3。

#### 步骤 3.3 — 选择输出格式

AI 询问用户偏好的文件格式：

> **请问您希望生成什么格式的文件？**
> - **Word + Excel（推荐）**：生成 .docx 和 .xlsx 文件，适合非技术人员审阅
> - **Markdown**：生成 .md 文件，适合开发人员编辑
> - **全部都要**：同时生成两种格式

用户选择后进入步骤 3.4。

#### 步骤 3.4 — 创建项目文件（确认后）

AI 根据用户选择的格式生成文件。例如选择 **Word + Excel**：

```
智慧园区建设项目/
├── project-data.json
├── 项目启动方案.docx
├── 项目任务清单.xlsx
├── 01-项目立项/
│   └── 项目立项书.docx
├── 02-项目计划/
│   └── 项目计划.docx
├── 03-设计方案/
│   └── 设计方案.docx
├── 04-项目执行/
│   └── 项目进度报告.docx
├── 05-会议纪要/
│   └── 会议纪要.docx
├── 06-技术资料/
│   └── 技术资料.docx
├── 07-验收资料/
│   └── 验收报告.docx
└── 08-项目经验/
    └── 项目总结.docx
```

选择 **Markdown**：

```
智慧园区建设项目/
├── project-data.json
├── README.md
├── plan.md
├── tasks.md
├── risks.md
├── 01-项目立项/ → 项目立项书.md
├── 02-项目计划/ → 项目计划.md
├── ...
└── 08-项目经验/ → 项目总结.md
```

选择 **全部都要**：

```
智慧园区建设项目/
├── project-data.json
├── 项目启动方案.docx + 项目任务清单.xlsx
├── README.md + plan.md + tasks.md + risks.md
├── 01-项目立项/ → 项目立项书.docx + 项目立项书.md
├── ...
└── 08-项目经验/ → 项目总结.docx + 项目总结.md
```

### ⚠️ 风险识别

| 编号 | 风险类型 | 风险描述 | 影响 | 应对措施 |
|------|---------|---------|------|---------|
| R1 | 🔴 技术 | 子系统接口标准不统一 | 高 | 提前制定接口规范 |
| R2 | 🔴 供应链 | 关键设备采购周期长 | 高 | 提前确认供应商 |
| R3 | 🟡 管理 | 涉及部门多，协调成本高 | 中 | 建立例会制度 |
| R4 | 🟢 进度 | 工期紧张 | 中 | 设置质量检查点 |
